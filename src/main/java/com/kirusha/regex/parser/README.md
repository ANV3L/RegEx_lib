# Parser (Синтаксический анализатор)

## Ответственность
Парсер получает результат работы лексера (`LexerResult`) и строит
абстрактное синтаксическое дерево (`AST`) регулярного выражения.

Парсер отвечает за:
- структуру выражения;
- приоритеты операторов;
- неявную конкатенацию;
- нумерацию групп захвата;
- разбор скобок, повторов, наборов символов, epsilon;
- подготовку дерева для дальнейшего этапа: AST → NFA.

---

## Контракт

### Input
`LexerResult` — результат работы лексера.

Содержит:
- `List<Token>` — поток токенов;
- `String originalInput` — исходная строка regex.

Пример входных токенов для `(a|b)*c`:
- `LPAREN`
- `CHAR(a)`
- `PIPE`
- `CHAR(b)`
- `RPAREN`
- `STAR`
- `CHAR(c)`

### Output
`ParserResult` — результат синтаксического анализа.

Содержит:
- `ASTNode root` — корень AST;
- `int groupCount` — количество групп захвата, пронумерованных по порядку открытия `(`;
- `String originalInput` — исходная строка regex для последующих этапов и отладки.

---

## Ошибки
При некорректной последовательности токенов выбрасывается `ParserException`.

Примеры ошибок:
- незакрытая скобка: `(ab`
- лишняя закрывающая скобка: `ab)`
- пустой повтор: `a{}`
- повтор без числа: `a{b}`
- неожиданный токен в позиции, где ожидался атом
- пустая правая или левая часть альтернации: `a|`, `|a`
- некорректная структура набора символов: `[` без `]`

---

## Приоритеты операторов

Парсер должен соблюдать приоритеты:

1. Повторы:
   - `*`
   - `{n}`

2. Конкатенация:
   - `ab`

3. Альтернация:
   - `a|b`

То есть:
- `a|bc*` = `a | (b (c*))`
- `(a|b)c` = `((a|b) c)`

---

## Грамматика (рабочая модель)

regex        -> union
union        -> concat ('|' concat)*
concat       -> repeat+
repeat       -> atom ( '*' | '{' NUMBER '}' )*
atom         -> CHAR
             | EPSILON
             | BACKREF
             | charClass
             | group

group        -> '(' regex ')'
charClass    -> '[' charClassItem* ']'
charClassItem-> CHAR | escaped-meta | NUMBER | EPSILON

---

## Замечания по группам захвата
Каждая пара круглых скобок `(r)` рассматривается как:
1. операторная скобка для изменения приоритета;
2. группа захвата.

Нумерация групп ведётся по порядку встречи открывающей скобки `(`:
- `(a)` → group 1
- `(a(b))` → outer = 1, inner = 2
- `((a)(b))` → outer = 1, second = 2, third = 3

---

## Замечания по []
Набор символов `[abc]` представляется в AST отдельным узлом `CharClassNode`.

Особенности:
- `[abc]` означает один символ из множества `{a, b, c}`;
- `[]` допустим и интерпретируется как epsilon (по условию допускается пустой набор, аналог `#`);
- на этапе parser не нужно разворачивать `[abc]` в `a|b|c`, это можно сохранить как отдельный тип узла.

---

## Замечания по backreference
Токен `BACKREF` (`\1`, `\2`, ...) должен быть сохранён в AST отдельным узлом.
Даже если полная поддержка backreference будет делаться позже или как доп. баллы,
парсер должен уметь построить корректное дерево.

---

## Передача дальше
Парсер не занимается автоматами.
Следующий этап:
`ParserResult` → `ThompsonBuilder` → `NFA`

---

## Основные сущности
- `Parser` — основной синтаксический анализатор;
- `ParserResult` — объект-отчёт;
- `ParserException` — ошибка синтаксического анализа;
- `ASTNode` и наследники — узлы дерева.
