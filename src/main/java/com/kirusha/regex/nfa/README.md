# NFA (Недетерминированный конечный автомат)

## Что это такое
NFA = Nondeterministic Finite Automaton.

Это промежуточное представление регулярного выражения в виде графа состояний,
которое строится из AST и затем преобразуется в DFA.

В рамках проекта NFA используется для:
- стандартной компиляции regex: AST -> NFA;
- дальнейшего преобразования в DFA;
- поддержки групп захвата (в перспективе);
- поддержки более гибкого матчинга на этапе, где DFA ещё не построен.

---

## Ответственность пакета
Пакет `nfa` отвечает за:
1. представление недетерминированного автомата в памяти;
2. хранение состояний и переходов;
3. построение NFA из AST методом Томпсона;
4. передачу результата дальше в этап DFA-construction.

---

## Контракт

### Input
`ParserResult`

Содержит:
- `ASTNode root` — корень синтаксического дерева;
- `int groupCount` — количество групп захвата;
- `String originalInput` — исходная строка.

### Output
`NFA`

Содержит:
- стартовое состояние;
- принимающее состояние;
- множество всех состояний;
- алфавит автомата;
- при необходимости — количество групп.

---

## Основные сущности

### NFAState
Состояние НКА.

Хранит:
- уникальный идентификатор;
- переходы по символам;
- epsilon-переходы.

### NFA
Полный объект автомата.

Хранит:
- startState;
- acceptState;
- все состояния;
- алфавит.

### NFAFragment
Промежуточная структура, используемая при построении по Томпсону.

Хранит:
- start;
- accept.

Используется как строительный блок:
каждый узел AST превращается в маленький фрагмент НКА.

### ThompsonBuilder
Преобразует AST в NFA.

---

## Как строится NFA

### LiteralNode(a)
Строится фрагмент:

start --a--> accept

### EpsilonNode
Строится фрагмент:

start --ε--> accept

### AlternationNode(left, right)
Строится новый start и новый accept:

        ε -> left.start
newStart
        ε -> right.start

left.accept  -> ε -> newAccept
right.accept -> ε -> newAccept

### ConcatenationNode(left, right)
left.accept соединяется с right.start через epsilon
или через слияние состояний, в зависимости от реализации.

### KleeneStarNode(child)
Создаются новый start и новый accept:

newStart -> ε -> child.start
newStart -> ε -> newAccept
child.accept -> ε -> child.start
child.accept -> ε -> newAccept

### RepeatNode(child, n)
Создаётся конкатенация из n копий child.

### CharClassNode([a,b,c])
Создаётся один start и один accept:

start --a--> accept
start --b--> accept
start --c--> accept

### GroupNode
На первом этапе можно строить так же, как child.
В дальнейшем здесь можно добавить метки начала/конца группы.

### BackReferenceNode
Полная поддержка backreference не является регулярной конструкцией.
На этапе ThompsonBuilder может быть:
- временно не поддержана;
- выбрасывать исключение;
- обрабатываться отдельно позже.

---

## Ограничения и замечания

1. На первом этапе допускается один accept-state на весь NFA.
2. Конструкция Томпсона должна быть чистой:
   - входной AST не мутируется;
   - результатом является новый NFA.
3. Для простоты тестирования полезно нумеровать состояния автоматически.
4. Позже NFA будет преобразован в DFA через subset construction.
5. Если в regex есть группы захвата, NFA может дополнительно хранить groupCount.
