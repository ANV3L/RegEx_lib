# Recovery (Восстановление регулярного выражения)

## Ответственность
Пакет `recovery` отвечает за восстановление регулярного выражения из скомпилированного DFA
методом исключения состояний (state elimination).

---

## Контракт

### Input
`DFA` — скомпилированный детерминированный конечный автомат.

### Output
`String` — регулярное выражение, описывающее тот же язык, что и входной DFA.

---

## Алгоритм (метод исключения состояний)

1. Преобразовать DFA в GNFA (Generalized NFA):
   - Добавить новое стартовое состояние с ε-переходом в бывший start;
   - Добавить новое принимающее состояние с ε-переходами из бывших accept states;
   - Метки на переходах — регулярные выражения (изначально — одиночные символы).

2. Последовательно исключать внутренние состояния:
   - Для каждого исключаемого состояния q_rip:
     - Для каждой пары (q_i, q_j), где q_i → q_rip и q_rip → q_j:
       - Обновить переход q_i → q_j: `R_new = R_old | (R_in)(R_loop)*(R_out)`

3. Когда остались только start и accept:
   - Регулярное выражение = метка перехода start → accept.

---

## Основные сущности

### GNFA
Обобщённый NFA с regex-метками на переходах.

Хранит:
- множество состояний;
- переходы: `Map<Pair<State, State>, String>` (regex-метки);
- единственный start и единственный accept.

### StateEliminator
Реализует метод исключения состояний.

Методы:
- `String recover(DFA dfa)` — основной вход;
- внутренние методы для преобразования DFA → GNFA, исключения состояний, упрощения regex.

---

## Замечания
1. Результат может быть не минимальным regex (алгоритм не гарантирует оптимальность).
2. Порядок исключения состояний может влиять на длину итогового regex.
3. Полезно реализовать базовые упрощения: `#|R = R`, `R# = R`, `#* = #`.
