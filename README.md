# Библиотека регулярных выражений

## О проекте

Проект был разработан в рамках изучения теории автоматов
Программа может использоваться как быстрый способ добавить в проект поддержку регулярных выражений, также проект разрабатывался в соответствии с парадигмой ООП, в связи с чем каждый может добавить необходимую ему логику

Изначально выбор стоял между CYK, CLR, LL(1) и "методом рекурсивного спуска" - ввиду сжатых сроков разработки, мною было принято решение выбора метода рекурсивного спуска, поскольку он легко реализуется, а также понятен большинству разработчиков

Быть уверенным, что библиотека будет работать при любом регулярном выражении можно благодаря теореме, которая гласит о том, что любой регулярный язык можно представить в виде конечного автомата

### Что еще можно добавить в проект
- При желании, можно легко дописать плагин-структуру для динамического расширения библиотеки

## Тестирование

Вся библиотека покрыта unit-тестами (Фреймворк JUnit 5)
coverage: 90%
branches: 80%

coverage не 100%, поскольку есть методы у классов, которые не используются по тем или иным причинам, допустим, у NFA есть метод to_string, который использовался для отладки и может быть использован для отладки в дальнейшем, поскольку во время компиляции "неиспользованные" методы не будут входить в байткод, то оставление их в проекте не только никак не повлияет на собранный проект, но и чуточку поможет при отладке проекта в будущем, если будет принято решение его дополнять

branches не 100%, поскольку в тестах не падаю во все ошибки

## Работа с библиотекой
```java
import com.kirusha.regex.Regex;

// Проверка совпадения строки с регулярным выражением
boolean matches = Regex.compile("i(v|c)t").matches("ivt") // true
```

## Какие символы поддерживаются

- '|' - альтернация
- '*' - замыкание клини
- '(', ')' - скобки для обозначения групп
- '[', ']' - начало/конец набора символов
- '{', '}' - начало/конец набора повтора
- '~' - пустая подстрока (Аналог епсилона)
- '#' - Операция XOR (Либо, либо)

## Какие операции поддерживаются

- Пересечение
- Объединение
- Разность
- Проверка на изоморфизм
- Проверка на эквивалентность языков

## Структура проекта

### Regex.java 

Точка входа в библиотеку регулярных выражений

#### compile pipeline
- Препроцессинг
- Запуск лексического анализа
- Запуск синтаксического анализа
- Построение НКА
- Преобразование НКА в ДКА
- Минимизация

### Lexer

Лексер основан на enum-классе TokenType.java
Для добавления нового символа достаточно добавить NAME_OF_ATOM('символ') в enum

### Parser

Были реализованы парселеты (Visitor pattern), ввиду чего для добавления алгоритма обработки нового атома необходимо лишь написать парселет и создать ему node для абстрактного синтаксического дерева, создание которого также облегчено добавлением интерфейсов UnaryNode и BinaryNode

В парсинге используется метод рекурсивного спуска с приоритетами (Pratt Parser)

### nfa

Строится НКА с помощью алгоритма Томпсона
Файл ThompsonBuilder.java реализован с заделом на расширяемость: есть map builders - словарь функций, которые отвечают за построение того или иного NFAFragment для алгоритма Томпсона, что позволяет разработчику дописывать класс за счет лишь добавления функции обработки нового node

### dfa

Преобразование НКА в ДКА.

### recovery

Восстановление регулярного выражения по автомату:
Работает с GNFA (Обобщенный НКА)
По теореме Клини из любого конечного автомата можно восстановить эквивалентное регулярное выражение, задающее тот же самый регулярный язык

С помощью данного класса (В совокупности с минимизацией конечных автоматов) можно проверять эквивалентность двух регулярных выражений или конвертировать произвольный граф переходов обратно в синтаксическое регулярное выражение

### operations

Операции над ДКА

На основе подекартового произведения с последующей минимизацией были разработаны операции пересечения, объединения и разности языков

В другом файле (DFAIsomorphism.java) присутствуют проверки на изоморфизм и эквивалентность двух ДКА


### engine

Движок, который проверяет matches строки и регулярного выражения
